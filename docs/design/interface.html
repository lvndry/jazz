01  /  Identity

One codepoint, three durations

The mark is a single quadrant pair. The wordmark is that pair extended into a two-voice rhythm. The activity indicator is that same pair given a life-cycle and multiplied across five lanes. One idea — offset, off the grid, more than one voice — expressed at three timescales, which is why the family reads as designed rather than assembled.

02  /  Waiting

An indicator that can count

A generalist agent's characteristic state is three things in flight at once — reaching into your inbox, a search and your calendar simultaneously. No existing tool's spinner expresses concurrency at all. This one does: idle lanes stay dark, so the number of moving lanes is the number of things actually running. The animation is an instrument, not a loading GIF.

▖░░░░ Five Lanes — the default Five lanes, each resting and then playing a three-step burst — ▖ opening, ▚ live, ▘ closing — on its own period of 3, 4, 5, 7 and 11 frames. Those are pairwise coprime, so the composite pattern runs 13 minutes before it repeats. A longer period just means a longer rest, so lane activity reads as how much is actually in flight. 345711 170ms
▞ Trade Fours — one tool Left cell calls, right cell answers. Maps exactly onto request and response, which is what a single tool call is. ▞ ▚ ▞ ▚ 180ms
▖ Swung Eighths — thinking One cell. Swing encoded by frame duplication: each downbeat is held two ticks and each upbeat one, which is literally what swung eighths are. The only design here that carries a groove in a single cell. ▖▖▘▝▝▗ 130ms
▚▞░░░░░░ Drift — indeterminate A lit window slides through a fixed track and wraps. Motion is continuous and directional, but because the window wraps instead of accumulating there is never a filled fraction to misread as a percentage. The split frame at the seam is what proves it's a loop and not a bar. ▚▞░░░░░░░▚▞░░░░░░░▚▞░░░░░░░▚▞░░░░░░░▚▞░░░░░░░▚▞░░░░░░░▚▞▞░░░░░░▚ 120ms

The rule

Never show a filling bar for something whose duration you don't know. Drift and Tide exist so there is always a truthful alternative — and because every glyph here is a filled area rather than a thin stroke, the identity survives on ink coverage alone. Monochrome costs contrast, never information.

Built to render identically everywhere

Every frame above is drawn from the quadrant and shade set — ▖▗▘▝▚▞ and ░. That range is fully present in all five target monospace fonts, it is East-Asian Neutral so a frame is the same width in every locale, and Warp renders it procedurally as exact rectangles that tile without seams. An indicator that is the same width on every machine is an indicator that can sit inside an aligned layout.

03  /  Layout

One window. One column. No panels.

A conversation is a vertical thing. Everything else in the interface is either above it or below it, and nothing sits beside it.

The live zone

A permanent answer to “what is happening”

A bounded region pinned directly above the input, holding one row per tool in flight and the current step of any multi-step task. It is always in the same place, so the question what is jazz doing right now has exactly one place to look — and because it sits against the input, it is already where your eyes are.

The input and footer are anchored to the bottom of the screen, so the zone grows upward and the transcript yields the rows — your typing never moves under your hands. It caps at five rows and collapses the rest to 2 more running.

And its height is a high-water mark for the turn, only shrinking after 800ms of stability, so a burst of fast tool calls can't make the transcript jitter. When nothing is in flight the whole zone disappears and the conversation reclaims the space.

One layout, every width

The same five regions at 80 columns and at 200. The header sheds detail by priority, the live zone caps its rows, and the conversation takes the width of the terminal. Nothing reflows into a different shape, so a session looks like itself on a laptop, on a monitor, and over SSH.

Two tracks, not one

The transcript is the width of the terminal. Running text takes that content column — rail on the left, two columns clear on the right — and a short flush-right strip holds timestamps and lane labels once the frame is wide enough that they would otherwise sit on the sentence.

Tool rows, entity lists, tables and code fences take the same full content width, because those are scanned rather than read.

04  /  The design

Instrument

Near-monochrome graphite under a single electric cyan, where every emphasis is carried by stroke weight rather than another colour. The signature runs the full height of the window — a one-cell rail through logo, transcript, input and footer — whose weight encodes depth and whose colour encodes state. Its designer calls it a bar line: music’s own notation for “a passage begins here.”

One glyph, one meaning

╶ means the agent is speaking. ▐ means the agent is asking for authority. Same geometry — a mark hugging the text on the same side — at an 8:1 stroke-weight ratio, so the house law is expressed literally rather than as a change of shape. And ▐ appears nowhere else in the entire product, which makes it the one mark you learn instantly and never misread.

jazz without a single extra colour

The vocabulary carries the personality. Sessions are sets. Delegations are lanes. Parallel work is a section. The rail is a bar line. Waiting copy is idiomatic and never jokey — comping behind you, two horns out, digging the crates — and the dial that tunes it sits in the footer next to the mode, so the personality is visible and adjustable rather than imposed.

The surplus width has a job

Prose is measured to 88 columns; the 27 columns left over become a flush-right metadata column for timestamps, elapsed times and ok/failed. A hard left margin for reading, a hard right margin for status, and no possibility of the two colliding. Full-width tracks — tool rows, entity lists, tables, code — opt in separately.

A settled tool call is a receipt

This is where most of the clutter went. A finished tool call used to show its invocation, arguments, status word, duration and result count — five facts at the same visual weight as a sentence of the answer. Now it reads gmail  4 flagged of 26 in dim text, with everything else behind one key. Tools are loud only while they are working, and become quiet receipts the moment they finish.

Verdict

The one I would ship. It is the calmer of the two, it needs the fewest colours to work, and its accent is an exact xterm-256 cube vertex so it is byte-identical over SSH. The rail gives it a signature that costs one column, never animates, and replaces the badge-and-spinner clutter it would otherwise sit beside — it subtracts interface rather than adding it. And the personality reads as jazz through structure and language, which ages better than decoration.

05  /  The two laws

Every case decided in advance

Two rules do almost all the work. They're worth stating as laws because they settle arguments that would otherwise be re-litigated on every pull request.

Law one

Colour is semantics

Every hue must answer the question “what is this?” — who is speaking, is this a tool, did it work, should I worry, is this about to touch my real accounts. That's six questions, so six hues. Everything else — every heading, rule, border, label, timestamp, path — lives on the neutral ramp.

Six hues is a small enough set to hold in your head, which is the whole point: after an hour in the app you read colour without deciding to. Cyan is jazz speaking. Amber is a scope you should notice. Green happened, red broke. Nothing is coloured to look nice, so every colour on screen is information.

Emphasis comes from here
▏▎▍▌   ─ ━ ═   ░▒▓█

Stroke weight, rule weight, shade density. Plus indentation, which carries more hierarchy than colour ever will and costs nothing.

Law two

Motion is allowed where text is not

While the model is silent, the interface is free to move — that is the one moment when motion is pure information and costs you nothing. The instant a token lands, everything except the status line goes still, and the only thing in the frame that changes is the sentence you're reading.

WaitingFull indicator. The only free delight budget you have.
StreamingIndicator stops. Nothing in the frame moves but the text.
Tool startsBlock appears at full height. No expand animation — growing blocks reflow text above them.
Tool endsGlyph swaps in place. A swap is legible; a fade is latency you invented.
InterruptIndicator freezes mid-frame and dims. A frozen frame is the truest picture of “stopped”.
06  /  The approval card

The most important object in the product

A coding agent asks permission to edit a file you can revert with git checkout. jazz asks permission to send an email, write to your calendar, or post in a Slack your colleagues read. There is no undo. Four designers worked this block independently, in four incompatible aesthetics, and converged on nearly the same rules. That agreement is worth more than any one of the treatments, so it is the spec.

RuleWhy
It is a different class of objectWhatever the direction's visual language is, this block breaks it in one deliberate way — elevation, bezel weight, or the absence of the signature effect. It must never look like another log line.
Name the real account, verbatimNot “your calendar” — you@example.com. The entire trust argument is that jazz always tells you which real-world object is in scope.
Every resulting field, before you commitTitle, exact time with timezone, every attendee, which calendar. Nothing may be discoverable only after pressing enter.
Irreversibility stated in prose“Not undoable from jazz — the invite leaves immediately.” A sentence, not an icon.
It reads as a decision, not a faultRed belongs to things that already broke. An approval is a choice you are being offered, and colouring it like an error is how people learn to dismiss errors.
It animates in, then holds perfectly stillStillness is what makes a card feel like a document you can read at your own pace. Motion that persists reads as pressure, and pressure on an irreversible choice is a dark pattern.
Controls outside the data frameThe card is what will happen; the line beneath is what you can do. Stops the accept affordance from ever reading as data.
Reject as available as acceptSymmetric placement, weight only via font-weight. Hiding the alternative is how consent theatre works.
“Always allow” is the least attractive thing on screenThe irreversible convenience option gets dim text. Findable, never inviting.
A distinct glyph for asking vs speakingHollow = the agent is speaking, solid = the agent is requesting authority. One codepoint carrying a real semantic distinction.
On failure, say what did not happen“nothing was written.” Silence about state is what destroys trust, and auth failure is this product's characteristic error.
Two rules that are latent safety bugs, not aesthetics

Pending keystrokes must be flushed when the card opens, or a character typed before it appeared gets consumed as the answer. And there must be a 250ms window where only deny is accepted. Denial should be instant; approval should never be a race with a stray y.

07  /  Reach

One design, four tiers

The base tier is the design, not a stripped-down apology for it. Everything above is absorbed silently when the terminal offers it.

Tier 0 — monochrome, CI, screen readers

Structure carries all meaning. Every glyph in the system is a filled area, so identity survives on ink coverage. No animation — state transitions become one log line each, which is strictly more informative in a CI log anyway.

Tier 1 — 256 colour, the floor

Every token has a verified xterm-256 index; the accent is an exact cube vertex, so it is byte-identical over SSH. This tier is where most sessions actually land, and it must not look like a compromise.

Tier 2 — truecolor + synchronized output

Exact hex, and flicker-free animation via DEC mode 2026, which brackets a frame so the terminal composites it atomically. Table stakes in Ghostty, kitty, WezTerm and iTerm2.

Tier 3 — protocol extras

Never load-bearing: OSC 8 so file paths are clickable, the kitty keyboard protocol for real chords, graphics protocols for inline image previews, OSC 66 so headings can actually be larger.

And the escape hatch, which is automatic

Fullscreen turns itself off with no flag when stdout isn't a TTY, when CI is set, under a screen reader, or below 60×12. An alternate screen with live repaint is actively hostile to a screen reader — the same region gets re-announced endlessly — so that one is not negotiable.

08  /  Everywhere

One design, from SSH to no terminal at all

The same interface has to hold on a box you reached through three jump hosts, in a terminal that shipped last month, and in a cron job with no screen attached. That is three different problems, and the design answers all three with the same material.

The floor — any 256-color terminal

Built for the far end of an SSH session

Every token in both palettes is an exact xterm-256 index, and both accents sit on real cube vertices — cyan is index 45, orange is 202 — so they are byte-identical over a link, not approximated. No truecolor is required for anything.

Every glyph is single-width in every locale, so a frame that lines up on your laptop lines up on a server with a different LANG. And because animation is quantised to whole cells and discrete colour steps, a high-latency link degrades the frame rate and nothing else.

The ceiling — Warp, Ghostty, kitty, WezTerm

More polish where the terminal offers it

Modern terminals get capabilities jazz detects and uses, never depends on: synchronized output for frames that composite atomically instead of tearing; procedural block rendering, where the mark, meters and rails are drawn as exact rectangles that tile seamlessly rather than as font glyphs; OSC 8 so file paths and sources are clickable; the kitty keyboard protocol for real modifier chords; and native desktop notifications when a long research run finishes while you are in another window.

All of it is progressive enhancement. Turn every one of them off and the design is unchanged in structure.

No terminal at all

Headless is a first-class surface

jazz already runs as a one-shot command inside a script, a scheduled workflow, a GitHub Action reviewing pull requests, and a bot on a server you own. So the design has to survive having no screen — and it does, because every state already carries a word: ok, failed, running, asking, renew, stopped.

Nothing is encoded in colour alone, so the fullscreen app collapses to a clean append-only log with one line per state transition — which is more useful in a CI log than a spinner ever was, and diffable.

The best consequence of designing for headless

The approval card doesn’t disappear when there is nobody watching — it travels. The same object, carrying the same fields and the same named account, reaches you wherever you are: as a full-width band in the terminal, as a message from a bot, or as a scoped decision a scheduled run is allowed to make on its own. It is the one component that has to render in three places, which is exactly why its content is specified as facts about what will happen rather than as a layout.

Same session, same memory

Because history became real data on disk rather than terminal scrollback, a conversation you started in the fullscreen app is the same conversation a headless run picks up, searches, and appends to. The interface changes shape; the session does not.
